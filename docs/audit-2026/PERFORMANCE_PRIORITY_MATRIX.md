# MOVIPadel Performance Priority Matrix — Phase 2A

## Ranking method

- **P0** — severe, user-facing, and potentially architectural.
- **P1** — major performance opportunity.
- **P2** — worthwhile optimization.
- **P3** — minor optimization.

Priority combines likely latency, request frequency, scaling behavior, and breadth of affected users. “Round trips” lists statically inferable browser/API and database operations; it is not a timing claim. “Live verification” indicates whether Supabase plans/cardinality are needed to validate severity or solution.

## Highest-value investigation order

1. **Instrument home and live-tournament traffic together.** They are the highest-frequency read paths and can multiply backend work by active users without an explicit action.
2. **Trace checkout/reward redemption end-to-end.** Capture database spans and provider timing separately; verify atomicity, locks, and retry semantics before considering changes.
3. **Profile circuit/ranking and ledger aggregation on production-scale data.** These contain confirmed N+1/full-history patterns and are likely to worsen as the application grows.
