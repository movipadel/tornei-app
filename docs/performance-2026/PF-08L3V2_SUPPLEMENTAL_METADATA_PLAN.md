## C. Security parity: PF-08 versus full baseline

### Required for PF-08 transaction testing

- PostgreSQL major-version compatibility and available UUID generation.
- `pgcrypto` availability in the same schema used by `extensions.crypt` and `extensions.gen_salt`.
- The local managed `auth.uid()` helper when applying/testing the existing RLS policies.
- Exact definitions of the 13 PF-08 tables, their direct references, checks, FKs, indexes, RLS state and policies; these are already in the raw dump.
- Effective schema/table access for `public` and the 13 PF-08 tables, sufficient to ensure the isolated test path uses the intended server/service role and does not accidentally grant browser roles broader mutation access.
- Explicit execute/owner/grant design for the future checkout/redemption RPCs. Those functions do not exist yet and will be a later PF-08 migration decision.

The exact owner and execute ACL of `set_staff_password` and `verify_staff_login` are **not required to test checkout/redemption atomicity**, because the current PF-08 flows do not invoke them. They remain required before importing a full public baseline that includes them, because `SECURITY DEFINER` functions with default/broad execution could be dangerous.

### Required for a full production-equivalent public baseline

- Owners and effective ACLs for all public tables, views, sequences and functions, not only the PF-08 subset.
- Default privileges relevant to objects created by applicable owners in `public` and globally.
- Extension inventory, schema placement and versions for every public-object dependency.
- Function security attributes, configuration and execute ACLs for every public function/procedure.
- Local verification of the managed schemas/functions used by public policies and functions.
- Resolution of the one non-PF-08 CHECK difference between the prior audit CSV and the current raw dump.

Exact ownership/grants for unrelated tournament tables are not needed to run isolated PF-08 concurrency tests. They are needed if the stated goal remains a full public-schema baseline rather than a deliberately scoped harness.

## E. SECURITY DEFINER findings

The raw dump contains two functions:

| Function | Confirmed properties | Risk to preserve/review |
|---|---|---|
| `public.set_staff_password(uuid,text)` | PL/pgSQL; `SECURITY DEFINER`; fixed `search_path` `public, extensions`; writes a password hash using `extensions.crypt`/`extensions.gen_salt` | Its owner’s privileges apply. Broad EXECUTE could allow an unintended caller to reset staff passwords. |
| `public.verify_staff_login(text,text)` | SQL; `SECURITY DEFINER`; fixed `search_path` `public, extensions`; reads `public.staff_users` and compares with `extensions.crypt` | Broad EXECUTE could expose an authentication oracle or bypass intended table access controls. |

For both, preserve the fixed search path and exact security mode only after verifying the production owner and effective execute ACL. Do not reproduce them under an arbitrary local owner and rely on PostgreSQL defaults. The minimum safe normalisation decision is explicit owner/definer strategy plus explicit REVOKE/GRANT policy in a later approved baseline/security task.

## F. PF-08L4 normalization requirements

PF-08L4 must normalize the reviewed raw dump rather than replay it. Required decisions/actions are:

1. remove dump header/footer, generated `\restrict`/`\unrestrict` directives, and dump-session `SET` boilerplate;
2. remove or carefully handle `CREATE SCHEMA public` and its comment because fresh Supabase already creates `public`;
3. remove `SET row_security = off`; retain each table’s RLS enable statement and each policy;
4. add only verified extension prerequisites, in their production-compatible schema, before public objects that require them;
5. preserve exact public DDL: columns/types/defaults, checks, keys, FK actions, indexes, views, functions and policies;
6. do not import production owners or ACLs blindly; translate them into a reviewed local security model once Q03–Q07 are known;
7. add no future PF-08 idempotency/RPC/constraint objects to the baseline migration;
8. keep the raw dump outside Git and create the migration only in PF-08L4 after this gate passes.
