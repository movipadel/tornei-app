## Divergenze da decidere prima della fase interessata

1. **“Non ancora giocati” non coincide con filtro attuale per data.** Un torneo terminato oggi può ancora comparire e avere live disponibile. Il requisito “passati admin-only” è accertato sull'elenco per data, non come divieto globale su tutti gli endpoint per ID o sugli archivi risultati circuiti. Non aggiungere filtri run o restrizioni endpoint durante il restyling; chiarire separatamente la semantica desiderata.
2. **Tutti nelle classifiche** non autorizza sommare gruppi. Può rimuovere il filtro livello nell'elenco dei gruppi, ma resta selezionato un solo ranking. Se non esiste un gruppo aggregato, nessuna nuova graduatoria.
3. **La tua posizione** non può usare il solo nome come prova. Il DTO pubblico non espone un collegamento univoco user→riga. Prima della personalizzazione occorre una lettura server verificata o fallback neutro senza attribuzione personale.
4. **Attività storiche**: cancellazioni tornei eliminano righe e gli admin possono eliminare tornei. L'aggregatore non promette uno storico completo né introduce soft-delete nel freeze.
5. **Profilo e tessera** sono nuove superfici approvate; i flussi sottostanti restano quelli esistenti. L'assenza di API modifica anagrafica non autorizza crearne una.

## Confine futuro operatori

Decisione congelata, implementazione esclusa: login UX unico admin/staff, ruolo server-side, privilegi separati. Flag device solo per visibilità icona; sessione privilegiata valida necessaria a ogni accesso. Sessione presente → accesso con un tap; assente → login unico. Il `PublicNav` attuale mostra già un accesso admin: non applicare ora la futura regola device.

Ogni fase futura deve confrontare input, risposta, effetti DB e notifiche con la baseline, separatamente dagli screenshot. Consultare [regressione](MOVI_APP_REGRESSION_PLAN.md). Un test che scopre un difetto preesistente apre una decisione distinta: non ne autorizza la correzione nel rebranding.
